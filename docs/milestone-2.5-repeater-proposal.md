# 规划 §3.5（中继器/比较器/侦测器相）的轻量实现方案

> 本文是 §3.5 的**设计提案**，尚未实现（本版只交付 §3.4 红石相）。
> 目标：在不复制 3×~300 个组合方块类、不做逐像素烘焙的前提下，拿到 §3.5 的核心玩法
> （元件按"露出红石相的面"输入/输出、元件挂在固相表面），并保留后续升级到逐像素渲染的空间。

## 1. 为什么不用规划里的原方案

规划要求"中继器/比较器每一平方像素搭在固相表面最高处"，即**烘焙期自定义网格**：读取宿主模型的顶面高度图，把杆/红条逐像素贴上去。
实测（§3.4 生成器）每个版本有 386 个可含相实例、每族组合方块状态 ~13.6 万——
若对 3 个元件再各生成一族，状态与类数量呈三倍增长，且逐像素网格要为每个版本维护一套烘焙管线。

## 2. 轻量方案：**单族"元件相"方块 + 宿主外形采样驱动的位置修正**

### 2.1 表示

只注册 **3 个**方块（不按宿主展开）：

| 方块 | 属性 | 说明 |
| --- | --- | --- |
| `liquidphase:repeater_phase` | `FACING`(4) × `DELAY`(4) × `POWERED`(2) × `HOST_SHAPE`(枚举 0–7) | 中继器相 |
| `liquidphase:comparator_phase` | `FACING`(4) × `MODE`(2) × `POWERED`(2) × `HOST_SHAPE`(枚举 0–7) | 比较器相 |
| `liquidphase:observer_phase` | `FACING`(6) × `POWERED`(2) × `HOST_SHAPE`(枚举 0–7) | 侦测器相 |

- `HOST_SHAPE` 是"宿主顶面高度档位"（0=平、1=1/8、2=2/8、…、7=最高 7/8 或台阶档），
  由放置时对宿主体积形状采样得到；模型按该档位整体上下平移（`display` 平移或 8 个预烘焙模型变体）。
  这样**同一方块**能贴合楼梯/台阶/墙/栅栏等不同表高，不需要为每个宿主注册一族。
- 状态数：`2 (repeater: 4×4×2×8) = 256`、`comparator: 4×2×2×8 = 128`、`observer: 6×2×8 = 96`——总计 **480 状态**，
  相比按宿主展开（数万级）小两个数量级。

### 2.2 位置

元件相占据**宿主方块格本身**（与红石相相同：把宿主替换为"含元件相"的表示），而不是相邻格。
渲染时元件贴在该格宿主顶面上、按 `HOST_SHAPE` 抬升，因此"水平方向每一平方像素搭在固相相应像素最高处"的效果
用**档位化高度 + JSON 模型平移**近似（真正的逐像素是后续升级项）。

### 2.3 信号语义（两个方案通用，也是规划要求的核心）

- **输入/输出面判定**沿用 §3.4 的 `RedstoneBlocks.exposed(state, dir)`（宿主碰撞形状判定该面是否被固相覆盖）。
- 中继器相：`getSignal(dir)` 仅当 `dir == FACING` 且该面露出时返回 15；输入从背面露出面读 `level.getSignal`。
- 比较器相：同上，另在 `getDirectSignal` 里读后方容器/信号强度；`MODE` 决定是否比较。
- 侦测器相：`FACING` 面前方的变化触发 `POWERED` 翻转，输出口（`FACING.getOpposite()`）露出时才输出 15。

### 2.4 与 §3.4 红石相的互操作

- 红石线/组合方块的"元件连接"判定复用 `RedStoneWireBlock.shouldConnectTo` 注入：把"元件相方块"当作信号源，
  但只有朝向该格的那一面露出时才算连接。
- 放置路径：红石相方块上用中继器物品右键 → 变为中继器相，`FACING` 取玩家朝向，`HOST_SHAPE` 取当前宿主档位。

### 2.5 渲染

- 3 个方块各 8 个 `HOST_SHAPE` 变体的 JSON 模型（杆 + 红条 / 五官 + 输出口），共用 1 套贴图；
  用 `display.translation` 或单独 8 个模型做高度档位。
- 探测面/输出口的朝向由 `FACING` 的 `y` 旋转表达（4/4/6 向）。
- 后续若要"逐像素贴面"，只需把 `HOST_SHAPE` 档位换成烘焙期高度图采样，其余信号逻辑不变（渲染与语义解耦）。

## 3. 交付顺序建议

1. 先做**中继器相**（唯一需要验证渲染档位+信号门控的最小闭环）；
2. 再铺比较器（多一个 `MODE` 与容器读取）；
3. 最后侦测器（`FACING` 6 向 + 计划刻翻转）；
4. 每步在 `AGENTS.md` 的测试矩阵里加一行，6 版本各跑一次服务端冒烟。

## 4. 明确不做（与规划一致）

- 活塞推动元件相（§8.3）。
- 26.x 实验性红石评估器下的一致性保证（§8.2）。
- 元件相与原版元件在同一格内的叠加显示（一格里只表达一个元件相）。
